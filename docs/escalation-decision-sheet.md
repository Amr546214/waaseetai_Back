# ورقة قرار: التصعيد الآلي للدعم والنزاعات

**الحالة الآن: التصعيد الآلي مقفول.** لا شيء في لوحة الإدارة يفعّله أو يُسند به أو يرسل منه. هذه الورقة وحدها المرجع للقرارات؛ اترك الخانات الفارغة حتى يقرر أصحاب القرار.

## ما الناقص في الإعدادات اليوم؟ (اقرأه حيًّا من الشاشة)
شاشة **«جاهزية التصعيد»** (`/supper-admin-overview/it/escalation-readiness`، للمدير الأعلى) هي مصدر الحقيقة؛ تقرأ إعدادات الخادم وحسابات الفريق لحظة فتحها، ولا تُسند ولا ترسل شيئًا. الشروط الستة كما تظهر فيها بالنص نفسه:
1. مسؤول تذاكر الدعم معرّف
2. مسؤول الدعم موجود ونشط ويملك الصلاحيات المطلوبة
3. مسؤول النزاعات معرّف
4. مسؤول النزاعات موجود ونشط ويملك الصلاحيات المطلوبة
5. مهل أول رد محددة صراحةً لكل أولوية
6. تاريخ بدء الاحتساب (UTC) محدد

كل شرط يظهر «متحقق» أو «ناقص» (أو «غير معروف» إن تعذّر التحقق) مع سطر السبب. حالات المسؤول في بطاقة «فحص المسؤولين» (الاسم الظاهر ← نص السبب الذي يظهر تحته):
| الحالة | تظهر في الشاشة | نص السبب |
|---|---|---|
| ELIGIBLE | مؤهَّل | نشط ويملك الصلاحيات المطلوبة |
| MISSING | لم يُحدَّد | لم يُحدَّد مسؤول |
| NOT_FOUND | غير موجود | الحساب المحدد غير موجود |
| INACTIVE | حساب غير نشط | الحساب غير نشط |
| NOT_STAFF | ليس عضو فريق إداري | الحساب ليس عضو فريق إداري |
| STAFF_INACTIVE | عضو فريق غير نشط | عضو الفريق غير نشط |
| LACKS_PERMISSION | تنقصه صلاحيات | لا يملك الصلاحية: ‹اسم الصلاحية الناقصة› |
| UNKNOWN | تعذّر التحقق | تعذّر التحقق |

## القواعد الثابتة الحالية
- **تذاكر الدعم:** أول رد من الإدارة مستحق بعد **48 / 24 / 8 / 2 ساعة** لأولوية منخفضة / عادية / عالية / عاجلة (قيم افتراضية مضمّنة في الكود؛ `SUPPORT_SLA_FIRST_REPLY_HOURS` يستبدلها وتعرض الشاشة مصدرها: «من إعداد صريح» أو «القيم الافتراضية المضمّنة» أو «إعداد غير صالح»). التذكرة المتأخرة بلا رد إداري تُسند لمسؤول الدعم.
- **النزاعات:** نزاع مفتوح أو قيد المراجعة أقدم من **168 ساعة (7 أيام)** لكل حالة، ثابتة في الكود وليست حسب الأولوية، يُسند لمسؤول النزاعات.
- تُعتبر فقط الحالات المنشأة من تاريخ البدء `CASE_SLA_FROM` فصاعدًا، والفحص كل 60 ثانية بعد التفعيل.

## 2. متطلبات المسؤولين
- **مسؤول الدعم:** عضو فريق إداري **نشط وغير موقوف**، حسابه نشط، ويملك `support.review` و `support.reply`.
- **مسؤول النزاعات:** عضو فريق إداري **نشط وغير موقوف**، حسابه نشط، ويملك `disputes.view` و `disputes.resolve`.
- الإسناد لا يمنح صلاحية: يجب أن يملكها الشخص قبل تسميته.
- **التحقق:** افتح شاشة «جاهزية التصعيد»؛ بطاقة كل مسؤول تعرض إحدى الحالات في الجدول أعلاه بنصها نفسه. لا تُعرض معرّفات ولا بريد.

## 3. متغيرات البيئة التي يقرؤها الخادم
| المتغير | المعنى |
|---|---|
| `SUPPORT_SLA_TARGET_ADMIN_ID` | معرّف حساب مسؤول الدعم |
| `DISPUTE_SLA_TARGET_ADMIN_ID` | معرّف حساب مسؤول النزاعات |
| `SUPPORT_SLA_FIRST_REPLY_HOURS` | أربع قيم مفصولة بفواصل بين 1 و720، مثل `48,24,8,2` (اختياري؛ بدونها تُطبَّق الافتراضية) |
| `CASE_SLA_FROM` | تاريخ البدء UTC |
| `CASE_SLA_ENABLED` | `true` لتشغيل العامل (غير مضبوط الآن) |

## 4. قائمة التفعيل (لم تُنفَّذ، NOT EXECUTED)
1. الفقرة 1 مكتملة وموقّعة أدناه.
2. ضبط المتغيرات الأربعة الأولى **دون** `CASE_SLA_ENABLED` وإعادة نشر الخادم؛ تأكد أن الشاشة ما زالت تقول «مقفول» وأن كل الشروط «متحقق».
3. اختيار تاريخ بدء مستقبلي، ثم ضبط `CASE_SLA_ENABLED=true` وإعادة النشر؛ يبدأ العامل مع العملية ويفحص كل 60 ثانية.
4. مراقبة أول الدورات (أحداث `TICKET_ASSIGNED` / `DISPUTE_ASSIGNED` في سجل التدقيق).
5. التراجع: حذف `CASE_SLA_ENABLED` وإعادة النشر.
