# ورقة قرار: التصعيد الآلي للدعم والنزاعات

**الحالة الآن: التصعيد الآلي مقفول.** لا شيء في لوحة الإدارة يفعّله أو يُسند به أو يرسل منه. هذه الورقة وحدها المرجع للقرارات؛ اترك الخانات الفارغة حتى يقرر أصحاب القرار.

## 2. متطلبات المسؤولين
- **مسؤول الدعم:** عضو فريق إداري **نشط وغير موقوف**، حسابه نشط، ويملك `support.review` و `support.reply`.
- **مسؤول النزاعات:** عضو فريق إداري **نشط وغير موقوف**، حسابه نشط، ويملك `disputes.view` و `disputes.resolve`.
- الإسناد لا يمنح صلاحية: يجب أن يملكها الشخص قبل تسميته.
- **التحقق:** افتح شاشة «جاهزية التصعيد» (`/supper-admin-overview/it/escalation-readiness`، للمدير الأعلى). بطاقة كل مسؤول تقول: مؤهَّل، أو لم يُحدَّد، أو غير موجود، أو حساب غير نشط، أو ليس عضو فريق، أو عضو غير نشط، أو تنقصه صلاحيات (مع اسم الصلاحية). لا تُعرض معرّفات ولا بريد.

## 3. متغيرات البيئة التي يقرؤها الخادم
| المتغير | المعنى |
|---|---|
| `SUPPORT_SLA_TARGET_ADMIN_ID` | معرّف حساب مسؤول الدعم |
| `DISPUTE_SLA_TARGET_ADMIN_ID` | معرّف حساب مسؤول النزاعات |
| `SUPPORT_SLA_FIRST_REPLY_HOURS` | أربع قيم مفصولة بفواصل بين 1 و720، مثل `48,24,8,2` (اختياري؛ بدونها تُطبَّق الافتراضية) |
| `CASE_SLA_FROM` | تاريخ البدء UTC |
| `CASE_SLA_ENABLED` | `true` لتشغيل العامل (غير مضبوط الآن) |

## 4. قائمة التفعيل (لم تُنفَّذ، NOT EXECUTED)
1. الفقرة 1 مكتملة وموقّعة أدناه.
2. ضبط المتغيرات الأربعة الأولى **دون** `CASE_SLA_ENABLED` وإعادة نشر الخادم؛ تأكد أن الشاشة ما زالت تقول «مقفول» وأن كل الشروط «متحقق».
3. اختيار تاريخ بدء مستقبلي، ثم ضبط `CASE_SLA_ENABLED=true` وإعادة النشر؛ يبدأ العامل مع العملية ويفحص كل 60 ثانية.
4. مراقبة أول الدورات (أحداث `TICKET_ASSIGNED` / `DISPUTE_ASSIGNED` في سجل التدقيق).
5. التراجع: حذف `CASE_SLA_ENABLED` وإعادة النشر.
