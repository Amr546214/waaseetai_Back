# KYC legacy-asset migration — NOT EXECUTED (local files only, not committed)

Moves the ~20 legacy PUBLIC KYC assets (Cloudinary `type=upload`) to `type=authenticated` and rewrites the stored value to the private
reference `private:<resource_type>:<format|->:<public_id>`. Run ONLY after the backend + frontend PRs are deployed together and the owner approves.

Expected rows (owner's read-only counts): PROD (waseetai_db): client front/back/supporting 2/2/2, provider front/back 4/4, provider certs rows 1,
onboarding 0, users.idDocumentUrl 0, proof_attachments 2, accreditation_samples with attachments 2 (public work samples: out of scope).
DEV (waseetai_db_dev): users.idDocumentUrl 1, proof_attachments 5, … (re-run the inventory for exact numbers).

## Order
1. `01-inventory.sql` (read-only) → `inventory.csv` per database. Review it by hand.
2. Backup (run by the team on the server): `pg_dump -Fc -t client_profiles -t provider_profiles -t client_onboarding -t users -t proof_attachments <db> > pre-kyc-migration.dump`, keep `inventory.csv`.
3. `node 02-rename-to-authenticated.js inventory.csv` — DRY RUN by default: prints what would be renamed, writes `mapping.dry.csv`. Nothing changes.
4. After approval: `CONFIRM=yes node 02-rename-to-authenticated.js inventory.csv --execute` (renames in Cloudinary, `invalidate:true`, writes `mapping.csv`).
   From this moment the old public URL stops working (404/401) — that is the goal. Do 3→5 in one maintenance window.
5. `node 03-generate-db-update.js mapping.csv > 03-db-update.NOT-EXECUTED.sql`, review, then apply in a transaction (guarded: `WHERE col = old_url`).
6. Verify: old public URL → 404/401; `POST /api/kyc-documents/access-link` opens the document for owner and admin.

## Rollback
`node 04-rollback.js mapping.csv --execute` renames the assets back to `type=upload`, and `04-rollback-db.NOT-EXECUTED.sql`
(generated by 03 next to the update) restores the old URLs. Or restore the dump (step 2).
